# 项目发现与周报

适用版本：0.1.1。2026-11-03 隔离测试及真实手动导入已验证，具体范围见项目 `docs/verification-0.1.1.md`。

- 先核对 `defaults.yaml`、`github.py`、`ranking.py`、`service.py` 和任务相关测试，不从历史采集数量推断当前网络可用。
- 每条 GitHub 查询是有限采样，不可描述成全站榜单。只有跨日 Star 快照才能计算净变化；首日无基线必须保持未知。
- 手动导入直接获取仓库与 README，不受高星/画像门槛限制，不修改完整扫描与自然日完成状态。数字 ID 去重，刷新不得覆盖个人研究状态。
- 五种研究状态为 pending/saved/studied/focus/studying；已研究不进入新周报，重点优先。旧 dismissed 保持排除，选新状态可解除；历史快照不可随迁移重写。
- 周报要求最近完整成功采集不超过七天。部分失败保留项目，但不得封存新的空周报来掩盖采集故障。
- 默认每周最多 3 项，热点最多 1 项；不足宁缺毋滥。同作者每期至多一项，历史 90 天排除。收藏只在达标后优先，忽略不进入未来选集，不修改历史选集。
- 周报按 ISO 自然周冻结元数据／入选理由，使用配置时区。GUI、CLI、Windows 任务共享业务锁和调度状态；重启只补当前周期，不堆积历史推送。
- 修改请求数量、默认查询、排序或 README 读取预算时，检查匿名限额、分支覆盖和热点读取名额，不能假定有 Token。
- 验证 `tests/test_workflow.py` 中周期、去重、部分失败、画像、证据不足与互斥行为。真实 API 只读可用于任务授权范围内联通验证，结果与模拟测试分别记录。
